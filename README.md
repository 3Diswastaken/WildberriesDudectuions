# Wildberries Deductions

Консольное приложение (CLI) на платформе .NET для автоматизированного сбора, агрегации и мониторинга критических бизнес-метрик (удержания за брак, подмены, зависшие ШК, тикеты сотрудников) по нескольким ПВЗ одновременно через закрытое API маркетплейса.

## 📌 Проблема
Управление сетью ПВЗ требует постоянного контроля финансовых удержаний и тикетов обратной связи. На официальном портале Wildberries эти данные распределены по 4 разным вкладкам для каждой отдельной точки (брак, подмены, зависшие ШК, тикеты). 

Ручной обход 4-6 пунктов выдачи занимал у куратора до 20 минут, требовал фиксации дедлайнов в сторонних таблицах и приводил к человеческим ошибкам - пропуску сроков регламентированного оспаривания штрафов.

## 🚀 Решение
Утилита агрегирует данные по всем ПВЗ аккаунта в единый интерактивный список, автоматически отсортированный по критичности дедлайна (времени, оставшемуся на ответ или оспаривание).

### Основные фичи:
- **Reverse-Engineered API:** Автономная работа с недокументированным API Wildberries (кастомная авторизация, поддержание сессии, локальная валидация JWT на истечение срока действия).
- **Интерактивный CLI:** Удобный интерфейс на базе `Spectre.Console` (управление с клавиатуры, мульти-выбор ПВЗ, просмотр истории движений товара и логов тикета по нажатию `Enter`).
- **Отзывчивый UX:** Использование анимированных спиннеров (`Status Context`) для визуализации процесса сетевых запросов и предотвращения ощущения «зависшего» терминала.
- **Стабильность:** Инструмент успешно прошел долгосрочное тестирование в реальных условиях эксплуатации (около 1 года активного использования без сбоев).

## 🛠 Технологический стек и Архитектура
- **Язык/Платформа:** C# 12 / .NET
- **UI-Presentation:** Spectre.Console (Interactive CLI)
- **Data Format / Storage:** JSON (с поддержкой абстракции хранилища — архитектура полностью готова к переключению на безопасное шифрование Windows DPAPI без изменения бизнес-логики).

### Архитектурные особенности кода:
1. **Слабая связанность (Loose Coupling):** Логика работы с сетью (`WbRequestService`), авторизация (`WBAuthService`), бизнес-клиент (`WbClient`) и UI изолированы друг от друга в соответствии с принципом разделения обязанностей (Separation of Concerns).
2. **Reliability (Надежность):** Реализована развитая иерархия кастомных исключений (`NetworkException`, `ApiException`). Все критические ошибки перехватываются UI-слоем, выводятся в понятном пользователю формате и приводят к безопасному завершению приложения (`Graceful Shutdown`).
3. **Data Processing:** Активное использование `LINQ` и строго типизированных доменных моделей для фильтрации, группировки и сортировки дедлайнов «на лету» (трансформация сырых DTO в Domain Models).
4. **Data-Driven API Client (Конфигурация через JSON):**
   - Сетевые запросы не зашиты в исходный код. Все параметры эндпоинтов (URL, HTTP-методы, структуры Payload и Headers) динамически считываются из внешних файлов конфигурации.
   - Реализована система склеивания метаданных: глобальные параметры окружения вынесены в `common-headers.json` и автоматически подмешиваются к специфичным запросам. Изменения в API со стороны маркетплейса изолируются на уровне JSON без необходимости пересборки приложения.
5. **Advanced CLI Presentation Layer (Продвинутый интерфейс терминала):**
   - **Полиморфизм в UI:** Реализован кастомный слой рендеринга разнородных объектов (`Ticket`, `DeductionGood`) внутри единого компонента выбора `SelectionPrompt<object>`. Типизация определяется в рантайме через паттерн-матчинг, данные выравниваются по колонкам для сохранения табличной структуры.
   - **Валидация ввода (Input Validation):** Все интерактивные запросы данных (ввод телефона, 2FA-кода) снабжены пре-валидацией строк на базе проверок платформы (`ValidationResult`) для обеспечения консистентности данных.
   - **UX-оптимизации:** Использованы адаптивные таблицы (`Table`), постраничный вывод (`PageSize`), безопасные циклы навигации по экранам деталей и безопасная обрезка длинных строк (`substring safe slicing`).
